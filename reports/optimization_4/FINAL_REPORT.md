## 2. Диагностика (DIAGNOSTIC_REPORT.md)

Разбор каждого вопроса содержит: вопрос, эталон и критерий оценщика, найденный контекст с рангами, релевантные фрагменты, черновик, удалённые утверждения с баллами NLI, результат рассуждения, причину и способ исправления.

## 4. Быстрый экспериментальный контур на RTX 3090

`scripts/linux/run_experiments.sh` + `research/opt4/steps.py`, `compare.py` и `live_report.py`.

**Гарантии:**
- Базовая линия `reports/runs/20261103T1310Z_rtx3090_main` только читается. Скрипт не стартует, если идёт бенчмарк.
- Используются исходные датасеты: файл проверяется по sha256 прогона, git на 3090 не нужен. Входные данные берутся сохранённые: контекст каждого вопроса восстанавливается из индекса прогона по id чанков, и текст сверяется с логом.
- Все промежуточные результаты сохраняются в `reports/optimization_4/live/<run>/`:
  - переписанный вопрос;
  - новый контекст;
  - каждая попытка проверки;
  - время каждого шага.
- Сравнение попарное с 1310Z. Отдельно считаются верные ответы, галлюцинации, ложные отказы и полнота составных ответов, на dev и test отдельно, плюс проекция на все 1307 вопросов.
- Регрессии ищутся автоматически: верные раньше и неверные теперь, а также новые галлюцинации. Найденная регрессия даёт код выхода 1 и пометку `REGRESSION` в SUMMARY.md.
- D0 проверяет, что 3090 воспроизводит залогированные черновики. Если нет, числа контура недействительны.
- `PLAN=e2e IDS=... FLAGS=...` - настоящий конвейер (`evaluate_suite.py --ids`) только на выбранных вопросах.

**Время.** Это оценка по медианам вызовов 1310Z, а не измерение. Фактическое время пишет лог.
- `PLAN=quick` (D0, G3, G4) - около 18 минут.
- `PLAN=all` (плюс e2e E1 с 20 контрольными и G2) - около 30 минут.

Проверено на ноутбуке без LLM: поддельный бэкенд, настоящие индекс, верификатор и логи. Восстановление контекста, D0 (6 из 6), путь замены ответа, оценка, отчёт и сравнение базовой линии с самой собой (1307 из 1307 совпали, 0 регрессий) работают. С настоящим llama-server контур ещё не запускался.

## 5. Изменения кода

- `generator_verifier.py`, `grounding.py`, `settings.py`:
  - `nli_anchor_scope` ("cited" | "document", по умолчанию "cited"): `_anchored()`, `claim_anchors(enhancements=)`, `is_identifier_anchor()`;
  - `nli_premise_unwrap_tables` (по умолчанию false): `unwrap_single_column()`;
  - с настройками по умолчанию поведение побайтно прежнее (B00).
- `evaluate_suite.py`: `--ids` (список или `@файл`). Документы и sha256 датасета остаются исходными.
- `research/opt3/data.py`:
  - колонки берутся по наличию в прогоне (1310Z - только judge);
  - датасет берётся из рабочей копии при совпадении sha256, иначе из git;
  - разбиение dev/test считается на датасетах прогона и совпадает с замороженным разбиением opt2 (тест).
- `research/opt4/`: diagnose, report, annotations.json, offline, retrieval, metrics, steps, compare, live_report.
- `scripts/linux/run_experiments.sh`.
- Тесты: `tests/test_opt4_variants.py`, `tests/test_research_split.py`. Весь набор: 314 прошли, 1 пропущен (POSIX-only на Windows).

  - Ни одно изменение не прошло все критерии: E1 безопасен, но прирост только на test.
  - G2-G4 пока гипотезы.

  - E5 без триггера (цена);
  - ослабление правила предпосылки и подсказка о перефразе (этапы 2-3).

  - есть прирост на dev;

  - нет потерь.
  Затем идёт подтверждение через `PLAN=e2e` или полный прогон.

## 8. Оставшиеся проблемы

- **Модальные утверждения** («MAY», «может») и переводы с отрицанием («SHALL NOT») получают низкую оценку NLI на верном тексте: V3-MH-002, V3-MH-018. Нужна работа с NLI-моделью, а не с конвейером.
- **Единственная настоящая галлюцинация V3-ADV-029** (74 бита rand_b) осталась. E1 её не затрагивает: якорь «74» - число.
- **Оценщик XQuAD** засчитывает ошибкой обоснованные отказы (14 вопросов «текст не утверждает»). Эталоны не менялись по правилам задачи.
- **Сегментатор** делит «Y. pestis» на утверждение «p.» (V3-XQFEN-163). Правка мелкая, вне плана.
