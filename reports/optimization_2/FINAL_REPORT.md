# FactRAG-NLI 2.0: итоговый отчёт оптимизации (RTX 3090)

Ветка `factrag-opt2` (влита в `rtx3090-linux`), отчёты - `reports/optimization_2/`, код
исследования - `research/opt2/`. Исходный отчёт и логи прогона 20261031T0508Z не изменялись
(читаются на месте); ответы оцениваются версиями датасетов этого прогона (git b058977, sha256
сверены), метки тестов не менялись.

## 1. Исходные показатели

Базовая линия - строка «thinking only on refusal (computed)» COMPARISON.md прогона 0508Z
(Qwen3.8-27B + bge-reranker-v2-m3, верификатор v2, рассуждение после отказа LLM в первом
черновике), воспроизведена по логам случай в случай (`BASELINE.md`):

| | Vanilla | FactRAG | Галлюцинации | Ложные отказы |
|---|---|---|---|---|
| v3 (220) | 90.5% | 85.5% | 2.2% (2/93) | 11.0% (14/127) |
| xquad-full (1087) | 90.9% | 89.7% | 0.0% (0/176) | 9.0% (82/911) |
| все (1307) | 90.8% | 89.0% | 0.7% (2/269) | 9.2% (96/1038) |

Вклад верификатора: FactRAG - Vanilla = -24 (исправлено 0, испорчено 24).

## 2. Первопричины ошибок (`PAIRED_ERROR_ANALYSIS.md`, `NLI_VERIFIER_RESEARCH.md`)

Из 144 неверных ответов базовой линии:

* **56 - отказ LLM при нужном чанке в контексте** (53 на XQuAD; у 46 нужный чанк на 1-м
  месте), в том числе после прохода с рассуждением; это консерватизм LLM на неудачно
  переведённых вопросах XQuAD, а не поиск и не проверка;
* **24 - верный черновик испорчен верификатором**: 14 - ошибка модели mDeBERTa (ложное
  противоречие на парафразе: «Стилерс проиграли Бронкосу» при «Бронкос победил Стилерс»,
  P(contradiction) 0.98), 8 - агрегация multi-hop (снята верная вторая часть ответа), 1 -
  правило большинства, 1 - буквальный поиск якоря;
* **37 опубликованных «неверных» ответов**: по ручной проверке 18 верны по смыслу, но не
  совпали с шаблоном оценки, 6 частично верны, 13 неверны; обе «галлюцинации» базовой линии -
  ложные срабатывания шаблона;
* **22 - поиск**: 13 отсечены гейтом, у 9 нужного чанка нет в контексте;
* 5 - неверный черновик снят проверкой (отказ вместо ответа).

Соответствие меток модели NLI, порядок premise/hypothesis и обрезка длинных пар проверены и
исправны. Найдены две уязвимости модели: лексическое перекрытие (верификатор v2 принимает
51.5% утверждений с подменённым ответом, 84% из них - по маршруту «окно» с порогом 0.8) и
заглавные ключевые слова RFC 2119 (P(entailment) 0.73 против 0.01 для того же текста строчными).

## 3. Что исправлено

| Ошибка | Решение | Результат (повтор 0508Z) |
|---|---|---|
| ответ, снятый проверкой, не получал второго шанса с рассуждением | проход с рассуждением для любого неопубликованного ответа | +11 верных, ложные отказы 96 -> 82 |
| ложные противоречия и удаление частей multi-hop | слой решений из двух моделей | 5 испорченных ответов возвращены (все multi-hop) |
| принятие ложных утверждений при лексическом перекрытии | слой решений | подмена ответа 51.5% -> 32.6%, отрицание 32.6% -> 13.6%, пересадка 13.3% -> 1.2% (test) |
| отказ LLM и после рассуждения | восстановление выборкой (2 черновика, T = 0.7) | +3 верных, ни одной новой галлюцинации на 44 контрольных |
| тихий переход PyTorch на CPU при сбое CUDA | `RAG_MODEL_DEVICE=cuda` | ошибка вместо многочасового прогона на CPU |
| вторая NLI-модель не помещалась в 24 ГБ | кодировщик вопросов на CPU | пик VRAM как в 0508Z |
| тесты setup.sh зависели от RTX-профиля | изоляция в `tests/conftest.py` | 303 теста проходят и под RTX-окружением (1 пропущен) |

Не исправлено (остаточные проблемы, раздел 12): отказы LLM на XQuAD, несовпадения с шаблоном.

## 4. Архитектурные изменения (`FINAL_ARCHITECTURE.md`)

1. **Слой решений** (`RAG_NLI_DECISION=judge`): mDeBERTa + bge-m3-zeroshot-v2.0 оценивают
   каждое утверждение по каждому процитированному источнику (чанк, окна, варианты с
   заголовком); 13 признаков сводит логистическая модель, обученная на dev; порог 0.3 выбран на
   dev при ограничении «ложные утверждения не чаще, чем у v2»; охранник якорей и вето
   противоречия сохранены; пять степеней обоснованности (supported, partially_supported,
   contradicted, ambiguous, insufficient_evidence). NLI - один из источников решения, а не
   безусловный фильтр, при этом LLM не может отменить отрицательное решение.
2. **Выборочное рассуждение**: проход с рассуждением для любого неопубликованного ответа
   (кроме гейта и бюджета контекста); проверены и отклонены 6 других поводов и режим правки.
3. **Восстановление** (`RAG_LLM_RECOVERY=sampling`): после отказа LLM и в проходе с
   рассуждением, при балле реранкера лучшего источника не ниже 0.5 - два черновика при T = 0.7,
   публикуется первый принятый проверкой. Не более 6 вызовов LLM на вопрос.
4. **Наблюдаемость**: степени и вероятности утверждений, флаги проходов рассуждения и
   восстановления в логах кейсов, параметры слоя решений с sha256 в `config.json` прогона.
5. **Конфигурация RTX 3090**: переключатель `VERIFIER=judge|rules`, загрузка второй модели в
   `setup.sh`, проверка в `verify_environment.py`, новые планы `run_benchmark.sh`.

## 5. Сравнение перспективных конфигураций (`METRICS_COMPARISON.csv`)

Повтор 0508Z на 1307 вопросах (dev 651, test 656); недостающие черновики сгенерированы на ПК
разработки тем же GGUF. Разница с базовой линией - парный бутстреп (2000 повторов) и точный
тест Мак-Немара.

|---|---|---|---|---|---|---|---|
| C0 базовая линия | 89.0% | 88.1% | 0.7% | 9.2% | - | - | 2.50 |
| C1 рассуждение для любого неопубликованного (v2) | 89.8% | 89.0% | 1.1% | 7.9% | +0.84 [+0.38, +1.38], 0.003 | +0.91 [+0.15, +1.83], 0.070 | 2.68 |
| C2 C1 + слой решений | 89.6% | 88.3% | 1.1% | 8.2% | +0.61 [-0.08, +1.30], 0.15 | +0.15 [-0.91, +1.37], 1.0 | 2.64 |
| **C4 C2 + восстановление (лучшая)** | **89.8%** | **88.6%** | **1.1%** | **7.8%** | **+0.84 [+0.15, +1.53], 0.043** | **+0.46 [-0.61, +1.68], 0.61** | **2.74** |

Pareto (точность / галлюцинации / ложные отказы / время): C4 и C5 не доминируют друг друга.
C5 точнее на 2 ответа (разница C4-C5 незначима), C4 в 1.3-11 раз реже принимает ложные
утверждения. По требованию «не получать точность ценой фактической надёжности» лучшей
выбрана C4; C5 доступна переключателем `VERIFIER=rules`. C9 (рассуждение правит отклонённый
ответ) на dev равна C4 (593 верных, 0 галлюцинаций), а на test на один ответ лучше и убирает
единственную настоящую галлюцинацию гибрида (V3-ADV-029); test не используется для выбора,
поэтому C9 - кандидат для живой проверки (`THINK_MODE=revise`), а не конфигурация по умолчанию.

## 9. Достоверность улучшений

* Против базовой линии на всём наборе C4 +0.84 п.п. (95% ДИ +0.15...+1.53, Мак-Немар p = 0.043);
  на независимой test-половине +0.46 п.п. (ДИ -0.61...+1.68, p = 0.61) - значимости нет.
  Основную часть выигрыша даёт повод для рассуждения (C1), выбранный на этапе f888cdf по всему
  набору; на test он даёт +0.91 п.п. (p = 0.07). Честная оценка: улучшение точности
  ответов реально, но мало (около +1 п.п.) и на половине набора статистически не доказано.
* Улучшение надёжности значимо: на test слой решений принимает 155 из 476 утверждений с
  подменённым ответом против 245 у v2 (разность 18.9 п.п. при n = 476), 56 из 411 отрицаний
  против 134, 11 из 915 пересадок против 122 - при 863 против 861 принятых верных из 907.
* Все пороги, коэффициенты и выбор между вариантами сделаны на dev; test использовался один
  раз на вариант. Отступление: повод «любой неопубликованный ответ» выбран в f888cdf по всему
  набору; здесь он перепроверен на test.
* Живая проверка интеграции на ПК разработки (RTX 5060 Laptop, тот же GGUF, лучшая
  конфигурация, 11 вопросов, отобранных по веткам конвейера): ошибок 0, верно 9; слой решений
  и восстановление сработали так же, как в повторе (V3-XQFRU-001, V3-MH-023, V3-TC-005 верны
  с первого черновика; V3-XQFRU-229 - верный ответ восстановлением), неверны V3-ADV-029 и
  V3-XQFEN-108 (несовпадение с шаблоном). Это проверка работоспособности, не оценка качества.
* Ограничения: повтор, а не новый живой прогон; недостающие черновики сгенерированы на ПК
  разработки (llama.cpp тот же, CUDA-ядра другие: черновики без рассуждения совпадали с 3090 в
  24 из 26 случаев); стресс-набор синтетический. Живой прогон `PLAN=main` на 3090 - проверка
  этих оценок.

| Конфигурация | Генерация на 1307 вопросов (часы 3090, по логам 0508Z) | Вызовы с рассуждением | Восстановление |
|---|---|---|---|

| базовая линия | 2.50 | 218 | - |
| C4 (лучшая) | 2.74 | 240 | 47 вопросов, 94 черновика |

Лучшая конфигурация в 2.5 раза дешевле «рассуждения всегда» и точнее его. Слой решений:
mDeBERTa 460 пар/с, bge-m3-zeroshot 287 пар/с (RTX 5060 Laptop, fp16), медиана 24 пары на
черновик - около 0.14 с на черновик на ноутбуке, меньше 0.1 с на 3090 при 4-20 с генерации.
Кодировщик вопросов на CPU - 61 мс. План `PLAN=main` - около 3.5 ч, `PLAN=full` - около 10.5 ч
с отдыхом GPU.

## 11. VRAM

Пик 0508Z - 23.2 ГБ из 24.6 (из них ~3.3 ГБ рабочий стол, ~17.2 ГБ llama-server, 2.65 ГБ
PyTorch). Вторая NLI-модель добавляет ~1.2 ГБ, перенос BGE-M3 на CPU освобождает ~1.1 ГБ:
ожидаемый пик ~23.3 ГБ. Квантование KV-кэша не нужно (у Qwen3.8 кэш только у 16 слоёв
внимания, 0.5 ГБ на 8192 токена). Без графического сеанса можно вернуть кодировщик на GPU
(`EMBEDDING_DEVICE=cuda`).

## 12. Остаточные проблемы

1. **Цели «галлюцинации не выше 0.7%» и «положительный вклад верификатора» на реальных
   данных не достигнуты.** Галлюцинации 1.1% (3/269): две из трёх - ложные срабатывания
   шаблона (V3-ADV-013 верно поправляет «в два» на «в три раза», V3-UNA-008 верно отвечает «ни
   один»), третья (V3-ADV-029, смежный факт вместо поправки «62 бита») появилась вместе с
   проходом рассуждения для любого неопубликованного ответа. Вклад верификатора на черновиках
   Qwen3.8 остаётся отрицательным (-11): эта LLM почти не ошибается фактами, а польза фильтра
   видна на ложных утверждениях (стресс-набор) и на более слабой LLM (Qwen2.5: 14 исправлений).
2. **Отказы LLM на XQuAD** (около 45 вопросов с нужным чанком на 1-м месте) не устранены ни
   рассуждением, ни подсказкой; выборка с температурой возвращает единицы.
3. **Шаблон оценки** занижает точность примерно на 1.4 п.п. (18 верных по смыслу ответов
   засчитаны как неверные); метки не менялись.
4. **Утечка рассуждения** при исчерпании бюджета (1 случай в сгенерированных черновиках):
   ответ теряется, но не публикуется.
5. Верные утверждения с несколькими источниками и в коротких чанках таблиц v3 подтверждаются
   хуже (87-89% против 96-99%).

## 13. Запуск лучшей конфигурации

```bash
bash scripts/linux/update.sh                         # если проект уже установлен
LLM_PROFILES=qwen38-27b-hybrid bash scripts/linux/setup.sh   # докачает bge-m3-zeroshot (~1.1 ГБ)
PLAN=main bash scripts/linux/run_benchmark.sh        # лучшая конфигурация, ~3.5 ч
PLAN=compare bash scripts/linux/run_benchmark.sh     # она же с VERIFIER=judge и rules, ~7 ч
bash scripts/linux/run_benchmark.sh                  # полный план с абляциями, ~10.5 ч
```

Ручной запуск: `bash scripts/linux/llama_server.sh start`, затем `source
scripts/linux/env.rtx3090.sh` и `demo.py` или `streamlit run app.py`. Установка на второй ПК -
`docs/RTX3090_LINUX.md` (разделы 8-11) и `УСТАНОВКА_ВТОРОЙ_ПК.txt`. Повтор исследования по
логам 0508Z: `python -m research.opt2.reproduce --run <папка прогона>`.
