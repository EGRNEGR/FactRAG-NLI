# Итоговая архитектура FactRAG-NLI 2.0 (RTX 3090)

Профиль по умолчанию `scripts/linux/env.rtx3090.sh`: `LLM_PROFILE=qwen38-27b-hybrid`,
`RERANKER=bge-reranker-v2-m3`, `VERIFIER=judge`. Параметры - `BEST_CONFIG.yaml`.

## Поток запроса

```
вопрос
  │
  ├─ поиск: BGE-M3 (dense, на CPU) + BM25 -> RRF -> 40 кандидатов
  │         -> bge-reranker-v2-m3 -> top-10; гейт: лучший чанк >= 0.005, иначе отказ
  │
  ├─ 1. черновик Qwen3.8-27B без рассуждения (T=0, seed 42, ≤512 токенов)
  │      └─ слой решений: каждое утверждение x каждый процитированный источник
  │           mDeBERTa + bge-m3-zeroshot по чанку, окнам по 2 предложения и вариантам
  │           «Заголовок. Раздел.» -> 13 признаков -> логистическая модель -> P(поддержка)
  │           публикуется при P >= 0.3, якоря (числа, коды) обязаны быть в источнике,
  │           вето при сильном противоречии; степени: supported / partially_supported /
  │           contradicted / ambiguous / insufficient_evidence
  │      └─ если ответ снят и есть утверждения: 1 исправление (revision с отклонёнными)
  │
  ├─ 2. ответ не опубликован (отказ LLM или проверки, кроме гейта и бюджета контекста)
  │      -> проход с рассуждением (enable_thinking, бюджет рассуждения 640, ≤1024 токенов)
  │         + та же проверка и 1 исправление
  │
  ├─ 3. снова отказ LLM и лучший источник >= 0.5 по реранкеру
  │      -> восстановление: 2 черновика без рассуждения при T=0.7 (seed 1000, 1001),
  │         публикуется первый, принятый проверкой
  │
  └─ ответ: только утверждения со степенью supported, каждое со ссылкой [S#];
     иначе канонический отказ
```

Не более 6 вызовов LLM на вопрос; повторная генерация никогда не публикуется без проверки,
LLM не может отменить решение верификатора.

## Что изменено относительно базовой линии 0508Z (89.0%)

| Изменение | Где | Эффект (повтор 0508Z, 1307 вопросов) |
|---|---|---|
| Проход с рассуждением для любого неопубликованного ответа, а не только после отказа LLM | `pipeline.think_retry`, `RAG_LLM_THINK_RETRY=refusal` (f888cdf, подтверждено здесь на test) | +11 верных, ложные отказы 96 -> 82 |
| Калиброванный слой решений из двух NLI-моделей | `generator_verifier.ClaimJudge`, `RAG_NLI_DECISION=judge` | ответы: -3 (в пределах погрешности); ложные утверждения test: 51.5 -> 32.6%, 32.6 -> 13.6%, 10.4 -> 7.9%, 13.3 -> 1.2% |
| Восстановление выборкой после отказа рассуждения | `pipeline._recover`, `RAG_LLM_RECOVERY=sampling` | +3 верных, 0 новых галлюцинаций на 44 контрольных |
| Кодировщик запросов на CPU | `RAG_EMBEDDING_DEVICE=cpu` | освобождает ~1.1 ГБ VRAM под вторую NLI-модель; +61 мс на вопрос |
| Только CUDA для PyTorch-моделей | `RAG_MODEL_DEVICE=cuda` | сбой CUDA - ошибка, а не многочасовой прогон на CPU |
| Степени обоснованности, вероятности и учёт проходов в логах | `claims[].grade`, `judge_scores`, `recovery_pass`, `decision` в config.json | анализ и воспроизводимость |

Итог: FactRAG 89.8% (1174/1307; v3 86.8%, XQuAD 90.4%), ложные отказы 7.8%, галлюцинации
1.1% (3/269); подробности и значимость - FINAL_REPORT.md.

## Что проверено и не включено

| Вариант | Почему нет |
|---|---|
| Пороги и маршруты верификатора v2 | движение по одной кривой: больше верных утверждений - больше ложных |
| Одна модель NLI крупнее (bge-m3-zeroshot, xlm-r-large-xnli, xlm-r-large-xnli-anli) | каждая хуже mDeBERTa хотя бы на одном виде ложных утверждений |
| Ансамбль min двух моделей | надёжнее, но -1.2...-1.4 п.п. ответов на test |
| Вердикт v2 как признак слоя решений (V31) | на dev равен V30, правило выбора - более простая модель |
| Нормализация ключевых слов RFC 2119 | на реальных черновиках эффекта нет |
| Поводы для рассуждения B-F (поиск, уверенность, конфликт, форма вопроса) | на test не лучше A при +5...+50% вызовов |
| Рассуждение всегда | 1172 против 1174 при 2.6-кратной стоимости |
| Рассуждение как правка отклонённого ответа (`THINK_MODE=revise`) | см. SELECTIVE_THINKING_RESEARCH.md |
| Восстановление подсказкой об источниках | 0 восстановленных ответов |
| Слияние реранкеров, маршрут по письменности вопроса | XQuAD хуже, гейт слабее, +1.1 ГБ VRAM |
| Адаптивный размер контекста | теряет нужные чанки multi-hop; A/B top_k 5 против 10: 28 против 37 |
| Изотоническая калибровка поверх слоя решений | ECE 0.045 -> 0.016, но AUC ниже, порог и так подобран на dev |

## Память RTX 3090 (24 ГБ)

| Компонент | VRAM |
|---|---|
| рабочий стол (GNOME, AnyDesk) | ~3.3 ГБ |
| llama-server: Qwen3.8-27B UD-Q4_K_XL, контекст 8192, KV только у 16 слоёв внимания | ~17.2 ГБ |
| bge-reranker-v2-m3 + mDeBERTa + bge-m3-zeroshot (fp16) | ~2.8 ГБ |
| BGE-M3 | 0 (CPU; на GPU только при построении индекса, до старта llama-server) |
| пик 0508Z / ожидаемый пик | 23.2 ГБ / ~23.3 ГБ |

Квантование KV-кэша почти ничего не даёт (гибридная архитектура: 0.5 ГБ на 8192 токена) и
не включено. SDPA используется XLM-R-моделями (BGE-M3, реранкер, bge-m3-zeroshot); у
DeBERTa-v2 её нет (eager). NLI в fp16: у bf16 вероятности одной пары заметно различались
между батчами с паддингом и без.

## Переключатели

```
VERIFIER=rules            # верификатор v2 (как в 0508Z); точность та же, защита слабее
RECOVERY=off              # без восстановления после отказа рассуждения
THINK_RETRY=llm_refusal   # рассуждение только после отказа LLM (базовая линия 0508Z)
THINK_MODE=revise         # рассуждение правит отклонённый ответ вместо нового черновика
EMBEDDING_DEVICE=cuda     # кодировщик запросов на GPU (если VRAM позволяет)
LLM_PROFILE=qwen38-27b    # без рассуждения; qwen38-27b-think - всегда; qwen25-14b - прежняя LLM
```
