## Условия и результат

До старта отсутствовали процессы llama-server и listener 8080. Весь рабочий
`data/qdrant`, включая BM25 JSON, перемещён в `.backup_indexes/<run>/original`.
Путь индекса перед запуском проверен как отсутствующий. Создан новый сервер
с `-ngl 35 -c 4096 -b 128 -ub 64 -np 1 --port 8080 --host 127.0.0.1`.

Production, fallback выключен; device/precision auto. Снимок nvidia-smi
зафиксировал Python и llama-server на RTX 5060. Нативный лог сохраняет CUDA
инициализацию. Индексатор BGE-M3 использует CUDA по штатному model_runtime;
ошибок CUDA/OOM нет. Снимок VRAM не является стресс-тестом или гарантией запаса.

Пресет `rfc-01`: Что означает код HTTP 204 No Content согласно RFC 9110?

Ответ: Код HTTP 204 No Content означает, что сервер успешно выполнил запрос и не имеет дополнительного контента для отправки в ответе. [S1]

NLI: verified. JSON и HTML содержат источники,
скоры и времена стадий. Это проверка запуска, а не повторная оценка holdout.

## Откат и проверки

Сервер остановлен автоматически через `stop_rag.ps1 -Force` после проверки
PID, пути и UTC-времени создания. Принудительная остановка явно отражена в логе;
она не объявляется graceful shutdown. Оригинальная база восстановлена,
SHA-256/размеры/относительные пути всех 4 файлов совпали; проверка
хешей повторена после pytest. Тестовая база удалена только после восстановления.
Резервная папка прогона остаётся пустой, рабочая база находится на прежнем месте.

После отката: **157 passed (15.37 с), mypy strict 30 файлов, Ruff чисто**.
PowerShell AST трёх скриптов разобран без ошибок.

Первый пробный запуск `20260906-010435-ccf03042`
потребовал вмешательства из-за ожидания наследуемых pipe-дескрипторов и сравнения
строки с DateTime после ConvertFrom-Json. Он сохранён отдельно и не считается
автономным результатом. Исправления: ожидание PID launcher через WaitForExit(int)
и сравнение UTC ticks. Успешный прогон выше выполнен после этих исправлений.

Артефакты: `.artifacts/cold-start/20260906-010736-e50697ce/`: cold-start.log,
cold-start.stderr.log, llama.stderr.log, timings.json, verification.json,
manifest-before.json, manifest-after.json, demo.json, demo.html, pytest/mypy/ruff.log.

points. При сбое отката копии сохраняются; `recovery.json` содержит точные пути.
