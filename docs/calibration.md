# Диагностика качества: этап 13

Калибровка выполнена на тех же 15 AI-размеченных вопросах. Это измерение на
обучающей для калибровки выборке, а не независимая оценка качества. Документы,
вопросы и эталонные ответы не менялись; после изменения размера чанков обновлены
ссылки разметки на chunk_id. SHA-256 снимка набора записан в каждом отчёте.
Гранулярность релевантных единиц изменилась: сравнение chunk-метрик с исходным
отчётом отражает одновременно ранжирование и новое разбиение. Например, в варианте
с 8 ответами Hit@5 гибридного этапа до реранкинга составил 50% вместо исходных 75%.

## Диагностика исходных отказов

Из 11 положительных отказов: четыре `relevance_threshold_not_met`, три
`context_budget_exceeded`, четыре `nli_verification_failed`. Последние три
переполнения бюджета нельзя приписывать отказу самой LLM: генерация не запускалась.
Поимённый список сохранён в `evaluation_report.json`, поле
`baseline_refusal_diagnostics`; текущая причина находится в `rows[].refusal_reason`.

Пары Cross-Encoder имеют порядок `(query, chunk_text)`. Проверка реальных входов
первого прогона обнаружила 7 пар длиннее 512 токенов из 900, максимум 528.
Небольшое превышение не объясняет все потери: существенны порог, упаковка контекста,
ошибки цитирования и NLI на русских утверждениях с английскими посылками.

## Изменения

- Cross-Encoder оценивает перекрывающиеся окна всего текста. Для чанка берётся
  максимальный sigmoid-score окна; порядок пары сохраняется. Окна считаются
  ограниченными батчами, включая хвост текста. Длины и число окон доступны
  в `response.retrieval_diagnostics`.
- Сортировка использует `alpha * normalized_rrf + (1-alpha) * rerank_score`.
  Нормировка: `normalized_rrf = rrf / ((w_dense+w_sparse)/(rrf_k+1))`.
  Без неё RRF и вероятность реранкера имеют несопоставимые масштабы.
  Исходные dense/sparse/RRF/rerank скоры сохранены; итоговый скор отдельный.
  Порог применяется к исходному rerank-score, до сортировки.
- Размер чанков 320/384 токена вместо прежнего большего размера уменьшает
  переполнение входа NLI. NLI не обрезает молча потенциальные исключения в хвосте.
- Для llama-server бюджет рассчитывается через локальный `/tokenize`, с резервом
  128 токенов на шаблон чата. Ошибка токенизатора не маскируется эвристикой.
- Утверждение принимается строго при `entailment > 0.4` и `contradiction < 0.2`
  для всех процитированных источников. Границы покрыты тестами. Удаляются служебные
  префиксы документа, а не содержательные условия исходного текста.
- Ограниченное исправление ответа по результатам NLI сохраняет все попытки и
  повторно проверяет результат теми же правилами. В выбранном профиле отключено:
  эксперимент не улучшил покрытие. Показатель всех попыток не скрывает отбраковку.
- Экспериментальный `nli_evidence_focus` выбирает BGE близкое полное предложение
  внутри цитируемого чанка, сохраняя соседние явные исключения. Реальная посылка
  записывается в `claims[].evidence[].premise_text`. Это не проверка противоречий
  во всём документе; удалённые условия могут потеряться. Режим ухудшил результат
  и отключён. При его явном включении NLI требует переданный encoder; pipeline
  передаёт существующую модель поиска.

Полные протоколы: `.artifacts/stage13/trial1.json` … `trial5.json`.
Заключительный прогон текущего кода записывается отдельно в `evaluation_report.json`.
Он завершён: 8/12 ответов, 3/3 негативных отказа, Hit@5 после реранкинга 83,3%,
0 технических ошибок. Цель 9/12 не достигнута. Остались `rfc-02`, `pg-01`,
`nist-04` (NLI) и `pg-04` (отказ LLM). Проверки: 148 тестов passed, mypy strict
для 28 файлов и Ruff без ошибок.
Измерения генерации могут различаться между прогонами; лучший исторический результат
не подменяет заключительный. «Ответ» здесь означает отсутствие канонического отказа
после NLI, а не экспертно подтверждённую полноту ответа.

Порог .05 исключает релевантный чанк pg-01 со скором .0385. Его снижение сохраняет
этот чанк, но ухудшило итоговое покрытие ответами и допустило негативы к генератору.
Поэтому одного глобального порога для достижения всех целей недостаточно.
В варианте с 8 ответами rfc-02, pg-01 и nist-04 заблокированы NLI, pg-04 — отказ LLM.

## Повторение

Используется запущенный локальный llama-server с `-ngl 35 -c 4096` и `/tokenize`.
Публичные параметры выбранного профиля для `.env`:

```dotenv
RAG_CHUNK_TARGET_TOKENS=320
RAG_CHUNK_MAX_TOKENS=384
RAG_RERANK_WINDOW_TOKENS=384
RAG_RERANK_RRF_ALPHA=0.8
RAG_RERANK_SCORE_THRESHOLD=0.05
RAG_LLM_TOKENIZER_MODE=llama_server
RAG_LLM_API_TIMEOUT=300
RAG_MAX_TOKENS=1024
RAG_NLI_ENTAILMENT_THRESHOLD=0.4
RAG_NLI_CONTRADICTION_THRESHOLD=0.2
RAG_GENERATION_REPAIR_ATTEMPTS=0
RAG_NLI_EVIDENCE_FOCUS=false
```

```powershell
python evaluate_quality.py --dataset ./data/golden_dataset.json
python scripts/analyze_calibration.py .artifacts/stage13/trial2.json --output .artifacts/stage13/ranking-sweep.json
python -m pytest tests/ -v
python -m mypy --strict settings.py model_runtime.py document_parser.py hybrid_retriever.py generator_verifier.py pipeline.py baseline_rag.py benchmark.py evaluate_quality.py app.py benchmark_ragas.py scripts tests
python -m ruff check .
```

Перебор ранжирования использует сохранённые скоры и не переоценивает генерацию.
Следующий шаг для независимой приёмки — экспертный аудит оставшихся цитат и
двуязычных NLI-пар, затем проверка выбранных правил на новых вопросах.
