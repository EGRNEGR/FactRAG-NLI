# Локальный RAG: требования и критерии приёмки

## Область и ограничения

Русскоязычные ГОСТ, СП, СанПиН, ТУ и регламенты в PDF, DOCX, TXT, MD.
До 500 страниц на документ, до 100 MiB на загрузку. Целевое оборудование:
одна GPU с 24 GB VRAM либо CPU с 32 GB RAM. p95 ответа < 3.5 с — цель,
проверяемая отдельно для каждого оборудования, размера корпуса и конкуренции.
Сканированные PDF без текстового слоя требуют отдельного локального OCR;
до его подключения парсер обязан отказать явно.

## Сценарии и проверяемый результат

| Сценарий | Критерий приёмки |
|---|---|
| Поиск допуска | Значение, единица измерения и условия с цитатой пункта и страницы |
| Сравнение требований | Оба требования и отдельные источники; различия без домыслов |
| Сложная таблица | Сохранены строка, составной заголовок, номер таблицы и страницы; продолжение связано только при подтверждённом номере |
| Исключения и сноски | Ссылка на сноску разрешена в пределах страницы/раздела; неоднозначность обозначена |
| Коллизии редакций | Версии показаны явно; при отсутствии основания выбирать актуальную — отказ от выбора |
| Атрибуция | Каждое фактическое утверждение имеет проверяемую ссылку на исходный чанк |
| Нет информации | Стандартный отказ; отсутствие контекста не заменяется знаниями LLM |

## Режимы и безопасность

Production — режим по умолчанию. Нет весов, токенов API, базы или совместимого
токенизатора — запуск завершается ошибкой. Development допускает эвристики
только при RAG_ALLOW_FALLBACK=true. Такая оценка не является оценкой нейросетевого RAG.
Модели загружаются с local_files_only=True, trust_remote_code=False. Offline-флаги
библиотек дополняются сетевой изоляцией на уровне ОС; они не заменяют firewall.
Пути документов разрешаются относительно document_root с проверкой resolve().
При конкурентной подмене симлинков требуется изолированный каталог, недоступный
для записи посторонним процессам; одна проверка пути не устраняет TOCTOU.

## Корпус и эксперимент

Версия набора: 2026-09-01. Приёмка требует минимум 50 реальных документов
с SHA-256 и метаданными версии и минимум 100 проверенных человеком вопросов
шести классов из задания. Синтетические тестовые документы не входят в этот корпус.
Разметка должна ссылаться на стабильные идентификаторы и страницы исходников.
До предоставления корпуса, локальных весов и независимой разметки измеренные
Faithfulness, Recall и Hallucination Rate отсутствуют. 0.92, 91.5% и 2.3% не результаты.

E0–E5 сравниваются на одном замороженном наборе, одинаковых весах генератора,
оборудовании и лимитах ответа. Сохраняются конфигурация, версии пакетов, хеши весов,
сырые ответы, контексты, NLI-скоры, ошибки и длительности. Ragas использует локального
судью; его оценка отделяется от ручной проверки. Таймауты и отказы не исключаются
из знаменателя без явного отчёта. Измеряются p50/p95, RAM/VRAM, Recall@K, MRR,
nDCG, Faithfulness, Context Recall/Precision, Answer Relevancy и доля галлюцинаций.

## Порядок реализации

Сначала этапы 0, 2, 3: этот контракт, settings.py, document_parser.py.
Далее инфраструктура и интеграция конфигурации в существующий конвейер,
корпус/разметка, реальные модели, benchmark, API, нагрузка и демонстрация.
Наличие нового settings.py само по себе не переводит старый API в production.
