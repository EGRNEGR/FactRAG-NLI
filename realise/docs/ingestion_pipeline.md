# Инкрементальная загрузка пользовательских документов

Реализованы `document_processor.py` и `scripts/manage_index.py`; в
`hybrid_retriever.py` добавлены чтение чанков документа, проверка полноты manifest
и пакетный upsert с одним обновлением BM25. Старый DocumentParser и его профиль
для golden/holdout не менялись. Новый профиль 650/800/75 настраивается отдельными
полями RAGSettings. PDF использует существующий PyMuPDF; скачивания и OCR нет.

SHA-256 берётся с временного снимка до парсинга. Дубликаты прежнего корпуса также
распознаются по document_id. Неполные документы после прерывания видны в --status,
но исключены из поиска. Повторная загрузка восстанавливает только этот хеш.
Пакет embeddings/upsert ограничен двумя чанками, inference_mode штатный.

## Реальный GPU smoke

Использована отдельная временная база, удалённая по завершении. В неё добавлен
первый документ, затем второй (пять чанков). Повтор второго — duplicate; поиск
первого документа сохранил прежний chunk_id. Итог: 2 документа / 6 чанков.

- Устройство: cuda:0, dtype: torch.bfloat16.
- Индексация второго документа после загрузки моделей: 0.427 с.
- CUDA allocated до/после: 2289734144 / 2289734144 байт.
- Peak allocated: 2362349056 байт (2.20 GiB).

Это короткий smoke на реальных весах, не стресс-тест совместно с llama-server.
Равенство allocated до/после подтверждает отсутствие роста живых CUDA-тензоров
в этом прогоне; оно не доказывает отсутствие всех утечек на любых документах.

Рабочая база после проверок: 3 документа / 1674 чанка,
неполных документов 0. Пользовательские тестовые документы
в рабочую базу не добавлялись. Полный holdout заново не пересчитывался.

## Эксплуатационные границы

- Embedded Qdrant имеет одного владельца-процесса. CLI необходимо запускать после
  закрытия другого клиента той же базы; внутри открытого pipeline допустим
  последовательный вызов DocumentProcessor.add(path, pipeline.retriever).
- Мы обрабатываем TXT/MD/PDF/DOCX через Scan и Web-загрузку. Мы извлекаем DOCX
  штатным Word-адаптером, сохраняя порядок абзацев, заголовки и таблицы.
  TXT/MD — UTF-8; сканированные PDF без текста требуют отдельного OCR.
- Длинное одиночное предложение/строка таблицы/метаданные отклоняются до записи.
  Overlap приближённый и может быть меньше целевого для длинных предложений.
- Qdrant пополняется, старые embeddings не пересчитываются. Статистика BM25Okapi
  пересчитывается на CPU для всего активного корпуса один раз после документа.
- Байтовое изменение файла создаёт новую версию, не удаляя прежнюю. Файлы
  хешируются и снимок удаляется, исходные пути остаются в метаданных.
- При штатном исключении записи клиент fail-closed; после аварии перезапуск
  восстанавливает BM25 и скрывает неполные документы. Транзакция не охватывает
  все файлы scan целиком; успешные файлы сохраняются.
